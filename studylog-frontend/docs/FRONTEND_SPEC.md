StudyLog Frontend Specification

1. 목표

사용자가 로그인한 뒤 카테고리를 만들고 공부 기록을 빠르게 작성·관리할 수 있는 반응형 SPA를 구현합니다.

화면만 존재하는 프로토타입이 아니라 실제 Spring Boot API에 연결된 완성된 CRUD 흐름을 목표로 합니다.

2. 사용자

주요 사용자는 개인 공부 기록을 간단히 남기고, 날짜와 카테고리별로 지난 학습 내용을 확인하려는 대학생 또는 취업 준비생입니다.

핵심 사용 흐름:

회원가입 → 로그인 → 카테고리 생성 → 공부 기록 작성
→ 대시보드에서 확인 → 상세 조회 → 수정 또는 삭제 → 로그아웃

6. 인증 상태 설계

전역 인증 상태에 최소한 다음 값을 둡니다.

interface AuthState {
  member: MemberResponse | null
  isAuthenticated: boolean
  isInitializing: boolean
}

초기 진입 흐름:

accessToken 없음
→ 비로그인 상태 확정

accessToken 있음
→ GET /api/members/me
→ 성공: 회원 상태 저장
→ 401: token 삭제 및 비로그인 상태
→ 네트워크 실패: 재시도 가능한 오류 상태

단순히 localStorage에 token 문자열이 있다는 이유만으로 유효한 로그인이라고 확정하지 않습니다.

9. 접근성

모든 입력에 연결된 label 제공

오류 메시지를 입력과 연결하고 가능하면 aria-describedby 사용

모달이나 확인 대화상자는 키보드로 조작 가능해야 함

아이콘 버튼에 aria-label 제공

텍스트와 배경의 대비 확보

:focus-visible 스타일 제공

로딩 상태는 텍스트 또는 접근 가능한 상태 설명 포함

10. 보안 및 데이터 원칙

소스 코드에 JWT, 비밀번호, JWT secret, DB 정보 저장 금지

token과 Authorization 헤더를 console에 출력 금지

dangerouslySetInnerHTML 사용 금지

사용자 입력 내용은 React의 기본 escaping으로 출력

memberId를 사용자 입력이나 URL에서 받지 않음

다른 사용자의 데이터 접근 오류를 클라이언트에서 우회하지 않음

12. 완료 확인 시나리오

인증

새 이메일로 회원가입할 수 있다.

올바른 계정으로 로그인할 수 있다.

로그인 후 새로고침해도 인증 상태가 복원된다.

token이 없으면 보호 페이지에서 로그인으로 이동한다.

잘못되거나 만료된 token은 제거된다.

로그아웃 후 개인 데이터가 화면에 남지 않는다.

카테고리

빈 카테고리 화면이 올바르게 표시된다.

카테고리를 생성하면 목록에 나타난다.

이름을 수정하면 즉시 반영된다.

삭제 전 확인을 받는다.

삭제 실패 시 백엔드 메시지를 확인할 수 있다.

공부 기록

카테고리를 선택하여 기록을 생성할 수 있다.

대시보드 목록에 기록이 나타난다.

상세 내용을 확인할 수 있다.

기존 값으로 수정 폼이 채워진다.

수정 내용이 상세와 목록에 반영된다.

삭제 후 목록에서 사라진다.

다른 회원의 기록 ID에 접근하려 할 때 안전한 오류 화면이 나온다.

품질

로딩 중 중복 요청 버튼이 비활성화된다.

백엔드가 꺼져 있을 때 연결 오류 안내가 나온다.

모바일 화면에서 주요 기능을 사용할 수 있다.

브라우저 콘솔에 관련 오류가 없다.

npm run lint가 성공한다.

npm run build가 성공한다.
